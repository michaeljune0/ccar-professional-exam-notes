■ 규정별 계약·경로

GDPR = DPA·SCC · FedRAMP = C4G·인가 클라우드 · SOC 2 는 증거 문서5.4 본편

왜 배우나 — 시험이 요구하는 것

시험 목표 5.4 규정 준수 · D5 규정·안전 14%
Ensure compliance with regulations (e.g., GDPR, HIPAA, FedRAMP)

이 개념으로 푸는 판단 (할 수 있어야 하는 것)

  • 5.4③ EU 고객·미국 연방 고객·보안팀 질문지 — 계약·경로·데이터 기본값은? — 규정 → 맞는 계약·배포 경로 고르기 + 데이터 정책을 범위·예외까지 말하기
  • 6.1③ 민감 데이터라며 BAA·GDPR·ZDR 을 한꺼번에 걸자고 한다 — 디스커버리에서 무엇을 사실로 확인하나? — 규정 약정을 데이터 사실(PHI 유무·거주지·보존)에서 끌어내기

한눈에

규정 이름을 보면 "무슨 계약" 또는 "어느 배포 경로"로 답이 갈림. 규정마다 붙는 곳이 다름 — GDPR 은 계약(DPA · SCC), FedRAMP 는 배포 환경, SOC 2 는 감사 보고서(증거 문서), HIPAA 는 조직 설정 + BAA ✓ 확인

비유 클라우드 공유 책임 모델 + 리전 선택. 고객 = 데이터 주인(관리자), 사업자 = 맡아 처리하는 쪽(처리자). 인가(authorization)는 서비스에 붙고, 감사 보고서는 사업자 문서 포털에서 받음

ELI5

나라마다 입국 서류가 다른 공항 같아요.

  • 유럽 손님은 "누가 짐 주인이고 누가 맡아 주는지" 적은 약속 문서가 필요해요.
  • 짐이 바다 건너 다른 나라로 가면, 건너갈 때 쓰는 약속이 따로 붙어요.
  • 미국 정부 손님은 허가받은 건물 안에서만 일할 수 있어요.
  • 점검 보고서는 "잘 관리해요" 라는 증명일 뿐, 약속 문서를 대신하지 않아요.

개념 설명

원리

규정마다 붙는 대상이 다르다

  • GDPR → 계약 관계. 누가 관리자(목적을 정함)고 누가 처리자(맡아서 처리)인지, 개인정보가 EU 밖으로 나갈 때 무슨 조항으로 지키는지. Anthropic 은 DPA 를 상용 약관에 편입해 두고, 역외 이전 조항(SCC)은 필요한 범위에서 참조로 끼워 넣음.
  • FedRAMP → 클라우드 서비스 인가(authorization). 모델은 부품이라 인가 대상이 아님. 그래서 답은 "어느 인가 환경에서 돌리나" = C4G 또는 인가 클라우드(Bedrock GovCloud · Vertex Assured Workloads).
  • SOC 2 → 감사 보고서. 보안 통제(control)가 돌아간다는 증거. 규정 계약이 아님.
  • HIPAA → 조직 설정 + BAA (이 카드 밖, ■ HIPAA 구성 · ■ BAA 적용 범위).

처리자가 누구냐가 먼저

  • 같은 Claude 모델이어도 부르는 길에 따라 처리자가 바뀜. 1st-party API · Claude Platform on AWS · Foundry 는 Anthropic, Bedrock · Vertex 는 그 클라우드.
  • 처리자가 바뀌면 보존·규정 문서도 그쪽 것을 봄.

핵심 질문 세 개

  • 이 규정은 계약·배포 환경·증거 문서 중 무엇을 요구하나?
  • 데이터는 어떤 길(1st-party / 클라우드 경유)로 흐르나 — 처리자가 누구인가?
  • 쓰려는 제품(앱 · API · Claude Code)이 그 인가 환경에 실제로 있나?

규칙 원문 ①②③④⑤⑥ (갈림길로 그린 규칙)
  1. ①

    GDPR : DPA 는 Anthropic 상용 약관(Commercial Terms)에 편입돼 계약의 일부. 고객 = 관리자(controller), Anthropic = 처리자(processor) (2026-09-28 조회) ✓ 확인 [5.4③] [6.1③]

    역외 이전 = SCC(표준 계약 조항) Module 2(관리자→처리자) · Module 3(처리자→처리자)가 필요한 범위에서 DPA 에 참조로 편입, 체결한 것으로 봄. 영국 = UK Addendum · 스위스 = Swiss Addendum. 충돌하면 SCC > DPA > 약관 (2026-09-28 조회) ✓ 확인

    하위 처리자(subprocessor) 추가는 미리 알림 → 고객은 15일 안에 이의, 없으면 동의로 봄 (2026-09-28 조회) ✓ 확인

  2. ②

    처리자가 누구냐로 적용 문서가 갈림 : Claude API · Claude Platform on AWS · Microsoft Foundry = Anthropic 이 처리자 → Anthropic 의 ZDR·HIPAA 문서. Bedrock · Google Cloud(Vertex) = 클라우드가 처리자 → 그 플랫폼의 보존·규정 문서 (2026-09-28 조회) ✓ 확인 [5.4③]

  3. ③

    FedRAMP : C4G(Claude for Government, FedRAMP High — 정부·계약자 모두) 또는 FedRAMP 인가 클라우드(Bedrock GovCloud · Vertex Assured Workloads) 중 하나여야 함(must). 표준 상용 API 는 이 목록에 없음. AWS Marketplace 상품은 Claude Enterprise 뿐이고 FedRAMP 아님 (2026-09-28 조회) ✓ 확인 [5.4③]

    인가는 모델이 아니라 배포 환경에 붙음 — 모델은 소프트웨어 부품, 고객은 호스팅 플랫폼으로 준수 상태 유지 ✓ 확인

    Claude Code 는 C4G 에 아직 없음 → FedRAMP 환경이 필요하면 Bedrock · Vertex 로 (2026-09-28 조회) ✓ 확인

    그 밖 (2026-09-28 조회) ✓ 확인 : ITAR = Bedrock(IL5)만 · CUI = C4G 또는 Claude Enterprise(제3자 NIST 800-171r3 증명) · IL6 = AWS Secret 리전 Bedrock · 주·지방정부 대부분 = Claude Enterprise

  4. ④

    SOC 2 = 증거 문서 : Anthropic 은 해마다 외부 감사를 받고, 고객이 서면 요청하면 감사 보고서·인증서(SOC 2 보고서 등)를 줌. 인증 목록·문서 요청 = Trust Portal(trust.anthropic.com). 공공 FAQ 가 드는 인증 = HIPAA · SOC 2 · ISO 27001 (2026-09-28 조회) ✓ 확인 [5.4③]

    SOC 2 보고서는 GDPR 계약(DPA · SCC)을 대신하지 않음 — 보안팀 질문지엔 증거로, 계약 칸엔 DPA · SCC 업계 일반

  5. ⑤

    HIPAA(PHI) → ■ HIPAA 구성 · ■ BAA 적용 범위. 공공 FAQ 의 "BAA 는 ZDR 계약이 필요" 문장은 플랫폼 docs("HIPAA readiness 면 ZDR 따로 필요 없음")와 부딪힘 → API 시나리오는 docs 쪽, 자세한 건 그 카드 (2026-09-28 조회) ✓ 확인

  6. ⑥

    여러 규정이 한 지문에 나오면 데이터 사실(EU 개인정보 · 연방 기관 · PHI)마다 해당 줄만 고름. 전부 한 묶음으로 요구하지 않음 업계 일반 [6.1③]

연습 문제

미 연방 기관이 FedRAMP 를 요구한다. 채팅은 C4G 로 정했고, 이번엔 개발팀이 쓸 Claude CodeClaude Code 차례다. 담당자는 "C4G 를 샀으니 Claude Code 도 거기서 쓰면 된다" 고 한다. Claude Code 는 어디로 가야 할까?

시험 대비

함정

  • ≠"EU 배포엔 DPA · SCC · SOC 2 인증이 필요" → SOC 2 는 증거 문서, GDPR 계약 칸은 DPA · SCC 업계 일반 공식 문장 없음
  • ≠"Anthropic 이 관리자(controller)" → 고객이 관리자, Anthropic 은 처리자 ✓ 확인
  • ≠"연방 고객에게 표준 상용 API" → C4G 또는 Bedrock GovCloud · Vertex Assured Workloads ✓ 확인
  • ≠"Claude 모델이 FedRAMP 인증을 받았다" → 인가는 배포 환경(클라우드 서비스)에 붙음 ✓ 확인
  • ≠"AWS Marketplace 로 사면 FedRAMP" → Marketplace 상품은 Claude Enterprise, FedRAMP 아님 ✓ 확인
  • ≠"C4G 에서 Claude Code" → 아직 없음, Bedrock · Vertex ✓ 확인
  • ≠"ITAR 도 C4G 로" → Bedrock(IL5)만 ✓ 확인
  • ≠"Bedrock 으로 불러도 Anthropic ZDR·HIPAA 문서가 적용" → 클라우드가 처리자 ✓ 확인
  • ≠"CUI 는 무조건 FedRAMP 환경" → Claude Enterprise 도 제3자 NIST 증명으로 가능 ✓ 확인

신호

"With respect to Customer Personal Data, Customer is the controller and Anthropic is Customer’s processor."

"is incorporated into and forms part of the Anthropic Commercial Terms of Service" (DPA)

"for the transfer of personal data to third countries" (DPA 의 SCC 정의)

"Customers requiring FedRAMP compliance must use Claude for Government (C4G) or access Claude models through FedRAMP-authorized CSPs (Bedrock GovCloud or Vertex Assured Workloads)."

"AI models are software components, not cloud services."

"ITAR data can only be processed in Claude via AWS Bedrock, which is IL5 accredited."

"audit reports or certificates applicable to the Services" (DPA F.1)

"On Bedrock and Google Cloud, the cloud provider is the data processor"

뒤집히는 때

1. "정부 고객 = FedRAMP 필수" 가 안 맞는 때

  • 조건 : 고객이 주·지방정부, 또는 CUI 만 다루는 기관.
  • 판단 : 주·지방정부 대부분은 Claude Enterprise 로 충분. CUI 는 Claude Enterprise 도 제3자 NIST 증명으로 가능. "정부니까 무조건 C4G" 는 과한 답.
  • 등급 : ✓ 확인
  • 근거 : 공공 FAQ en 11·23·47줄

2. 연방 기관이 Claude Code 도 원할 때

  • 조건 : 연방 기관, FedRAMP 필요, 채팅 앱 + 개발팀 Claude Code.
  • 판단 : 채팅 = C4G, Claude Code = Bedrock · Vertex(C4G 에 아직 없음). 한 경로로 다 묶는 보기는 틀림.
  • 시점 : 공공 FAQ 는 "올해 안" 출시 예정이라 적음 → 시점이 바뀔 수 있음(미해결 5).
  • 등급 : ✓ 확인
  • 근거 : 공공 FAQ en 11·13줄

3. EU 고객이 Bedrock 으로 부를 때

  • 조건 : EU 고객, 호출 경로 = Bedrock.
  • 판단 : 처리자는 AWS → Anthropic 의 보존·규정 문서가 아니라 AWS 쪽 문서를 봄. Anthropic DPA 가 그대로 적용되는지는 받은 원문에 문장 없음.
  • 등급 : 확인(처리자) · 계약 주체는 미해결 4
  • 근거 : api-and-data-retention en 7·250줄

4. 보안팀 질문지가 "GDPR 준수 증명" 을 SOC 2 로 요구할 때

  • 조건 : 질문지 한 칸에 "GDPR 준수를 SOC 2 보고서로 증명".
  • 판단 : 두 칸으로 나눠 답함 — 계약 칸 = DPA · SCC, 증거 칸 = SOC 2 보고서(서면 요청). SOC 2 하나로 GDPR 을 채우는 보기는 틀림.
  • 등급 : 업계 일반 (SOC 2 가 GDPR 요건이 아니라는 공식 문장 없음)
  • 근거 : DPA en 1·73·97줄

5. 공공 FAQ 가 "BAA 는 ZDR 필요" 라고 말할 때

  • 조건 : 주·지방정부가 PHI 를 API 로 다룸, 공공 FAQ 를 근거로 ZDR 까지 요구.
  • 판단 : 플랫폼 docs 는 "HIPAA readiness 면 ZDR 따로 필요 없음". API 시나리오는 docs 쪽. Claude Code 는 ZDR 이 있어야 BAA 대상 → ■ BAA 적용 범위.
  • 등급 : 확인(두 문장 모두 원문) · 공식 문서끼리 다름
  • 근거 : 공공 FAQ en 30줄 · api-and-data-retention en 49·234줄
