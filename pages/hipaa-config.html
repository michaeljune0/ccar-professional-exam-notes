■ HIPAA 구성

HIPAA configuration — BAA + HIPAA readiness + PHI 경계 · ZDR 불필요5.4 본편아래 설명 보기

카드

PHI(개인을 식별할 수 있는 건강 정보)를 Claude API 로 처리하려면 = BAA 서명 + HIPAA readiness 를 켠 조직 + 지원 기능만 + PHI 는 메시지 본문·첨부 같은 보호 칸에만(스키마엔 금지). PHI 면 HIPAA readiness 가 쓸 방식이고 ZDR 은 따로 필요 없음 (2026-09-28 조회) ✓ 확인

HIPAA readiness ≠ 즉시 삭제. 암호화·접근 통제(access control)·감사 로그로 PHI 를 수명 내내 보호하고, 데이터는 그 보호 아래 남을 수 있음. ZDR = 응답 뒤 저장 안 함. 둘은 덮는 기능 목록도 다름 ✓ 확인

비유 PCI 범위 줄이기. 카드 데이터는 전용 계정에만 두고 리소스 태그·메타데이터엔 안 넣음

지문

병원이 BAA 를 맺고 HIPAA readiness 를 켠 조직에서 진료 기록을 분류한다. 정확도를 올리려고 구조화 출력 스키마의 enum 에 환자 이름 목록을 넣자스키마 enum는 안이 나왔다. "HIPAA 조직이니 어느 칸에 넣어도 보호된다" 는 말도 있다. 환자 정보는 어디에 둬야 할까?

함정

  • ≠"ZDR 을 켜서 HIPAA 준수" / "HIPAA 에 ZDR 도 추가" → PHI + API 면 HIPAA readiness, ZDR 따로 필요 없음 ✓ 확인
  • ≠"BAA 만 서명하면 PHI 를 어디든" → 수락한 그 한 조직만 · 지원 기능만 · 보호 칸에만 ✓ 확인
  • ≠환자별 값을 구조화 출력 스키마 enum 에 → 스키마는 따로 캐시돼 같은 보호 없음 ✓ 확인
  • ≠"HIPAA readiness = 바로 지움" → 암호화·접근 통제·감사 로그. 즉시 삭제 아님 ✓ 확인
  • ≠"시범 끝나면 끄면 됨" / 한 조직에서 HIPAA·일반 업무 같이 → 켜면 영구, 따로 조직 ✓ 확인
  • ≠"AWS 를 쓰니 Claude Platform on AWS 로 HIPAA" → 거기선 HIPAA readiness 못 씀 ✓ 확인
  • ≠"HIPAA 면 아무것도 안 남음" → 법적 요구가 있거나 자동 안전 시스템에 걸리면 남을 수 있음(걸리면 입력·출력 최대 2년) ✓ 확인

ELI5

병원 환자 기록을 맡기는 특별 금고를 빌리는 거예요.

  • 금고를 빌리려면 약속서(BAA)에 도장을 찍고, 금고 모드(HIPAA readiness)를 켜야 해요.
  • 금고 모드는 한 번 켜면 못 꺼요. 그래서 일반 물건은 다른 창고에 둬요.
  • 환자 이름은 금고 안(메시지 본문)에만 넣고, 금고 겉 이름표(스키마)엔 쓰면 안 돼요.
  • "바로 버리는 창고"(ZDR)는 따로 안 빌려도 돼요. 금고가 이미 지켜 주니까요.

원리

두 약정은 푸는 문제가 다름

  • ZDR : 응답을 돌려준 뒤 프롬프트·응답을 저장하지 않음. "남기지 않기"로 지킴.
  • HIPAA readiness : 암호화·접근 통제(access control)·감사 로그로 PHI 를 수명 내내 보호. 데이터는 그 보호 아래 남을 수 있음. "남겨도 잠가 두기"로 지킴.
  • 그래서 PHI + Claude API 면 HIPAA readiness 하나로 충분. ZDR 을 더 붙인다고 HIPAA 가 되지 않음.
  • 덮는 기능 목록도 다름 (예 : 구조화 출력은 ZDR 에선 "qualified", HIPAA 에선 Yes · tool search 는 ZDR Yes, HIPAA No).

조직이 경계

  • HIPAA readiness 는 조직 단위로 강제. 그 조직 안의 요청은 전부 기능 제한을 받음.
  • 켜면 영구 → 일반 업무가 같은 조직에 있으면 일반 업무도 묶여 버림 → 조직을 나눔.
  • BAA 는 수락한 그 한 조직만 덮음.

PHI 는 "보호되는 칸"에만

  • 보호되는 칸 = 메시지 본문·첨부·파일 이름·메타데이터.
  • JSON 스키마는 생성 제약용 문법(grammar)으로 컴파일돼 따로 캐시(최대 24시간)되고 같은 보호를 못 받음 → 스키마에 환자 값 금지.
  • 워크스페이스 이름·사용자 정보·청구·지원 티켓은 애초에 PHI 가 없어야 하는 칸.

어디서 켜지나

  • Anthropic 이 처리자인 Claude API 에서만. Claude Platform on AWS·Microsoft Foundry 는 Anthropic 이 처리자인데도 HIPAA readiness 가 없음.
  • Bedrock·Google Cloud 는 클라우드 사업자가 처리자 → 그쪽 규정.

뒤집히는 때

1. "ZDR 불필요" 가 뒤집히는 곳 — Claude Code

  • 조건 : 같은 병원 개발팀이 PHI 가 섞인 저장소를 Claude Code 로 다룸.
  • 판단 : Claude Code 는 HIPAA readiness 대상이 아님 → BAA 를 받으려면 ZDR 을 켜야 함. API 앱과는 답이 반대.
  • 결과 : HIPAA API 조직 하나 + ZDR Claude Code 조직 하나 (둘은 한 조직에 공존 불가).
  • 등급 : ✓ 확인
  • 근거 : en-zero-data-retention 52줄 · en-privacy-baa 13줄 · en-covered-models-baa 49줄

2. 이름은 AWS 인데 답이 둘로 갈림

  • 조건 : "AWS 위에서 쓰고 싶다".
  • 판단 : Bedrock 이면 AWS 가 처리자 → AWS 규정. Claude Platform on AWS 면 Anthropic 이 처리자인데도 HIPAA readiness 가 없음 → 이 경로로는 PHI 불가.
  • 등급 : ✓ 확인
  • 근거 : en-zero-data-retention 1·49·50줄 · -full 254줄

3. 시범 조직에서 켜 버린 때

  • 조건 : 일반 챗봇을 돌리던 조직에서 "잠깐 시험해 보자"며 HIPAA readiness 를 켬.
  • 판단 : 영구라 못 끔. 그 조직의 일반 업무도 기능 제한(예 : Batch 막힘)을 받게 됨 → 처음부터 HIPAA 전용 조직을 새로 만드는 게 맞음.
  • 등급 : ✓ 확인 (영구·조직 단위·분리는 확인, "일반 업무가 막힘"은 그 두 사실에서 나온 결론)
  • 근거 : en-zero-data-retention 87줄 · -full 121·242줄

4. 최신 큰 모델이 필요한 때

  • 조건 : 진료 기록 요약에 Fable 5.1 이 필요.
  • 판단 : HIPAA-ready API 는 표준 보존이라 Covered Models 사용 가능. 반대로 "더 안전하게 ZDR 도" 를 붙이면 Covered Models 를 못 씀 → ZDR 을 더하는 건 손해만.
  • 등급 : ✓ 확인
  • 근거 : en-covered-models-baa 22·32줄 · en-zero-data-retention 99줄

미해결

  1. 켜는 절차가 공식 문서끼리 다름 : docs 는 "적격 조직은 Console 에서 직접 BAA 를 체결하고 켤 수 있음"(en-zero-data-retention 39·80~91줄, ko 80~93줄), privacy BAA 글은 "1P API 로 PHI 를 쓰려면 Primary Owner 가 BAA 에 서명한 뒤 Anthropic 담당·영업팀에 연락해 켜야"(en-privacy-baa 7줄). 시험이 절차를 물으면 "BAA 서명 + HIPAA readiness 조직" 까지만 확실.
  2. 공공부문 FAQ(en-public-sector-faqs 30줄)는 BAA 가 "It requires a Zero Data Retention (ZDR) agreement" 라 적음 → docs 의 "you do not also need ZDR"(39줄)와 반대. 같은 FAQ 가 "web search is excluded"(31줄)라 한 것도 지금 BAA 글(en-privacy-baa 74줄 웹 검색 대상)과 다름 → 옛 문장으로 봄(추론). 자세한 건 ■ BAA 적용 범위 미해결.
  3. 목록 5.4① 의 "규제 업무는 전용 조직으로 분리 = 근거 확인 필요, 추론" → 원문에서 확인됨(-full 121·242줄). 목록은 추론 표시였음.
  4. 목록 5.4① 의 "PHI 는 메시지 본문에만" → 원문은 첨부(이미지·PDF)·파일 이름·메타데이터도 PHI 가 나타나는 보호 칸으로 적음(58줄). 금지 칸은 스키마. 카드엔 고친 값.
  5. HIPAA Implementation Guide(Trust Portal PDF)는 받지 않음 — 서명한 BAA 와 이 가이드가 기능 목록의 최종 기준이라 docs·privacy 글과 다를 수 있음(미확인).
  6. Skilljar "Deploying Claude Enterprise with Confidence" 과정은 세션 skjd5-3 에서 미등록(Enroll 버튼) → 건너뜀.
