ELI5

보험 약관에 적힌 것만 보장되는 것과 같아요.

  • 병원 금고 약속서(BAA)는 목록에 적힌 방만 지켜 줘요.
  • 목록에 없는 방(Batch·파일 창고)은 문이 아예 잠겨 있어요.
  • 코드 도우미(Claude Code)는 "바로 버리기"(ZDR)를 켰을 때만 목록에 들어가요.
  • 그런데 바로 버리면, 오래 기억해야 하는 새 모델(Covered Models)은 못 써요.

원리

BAA 는 "조직 전체"가 아니라 "기능·제품 목록"을 덮음

  • 같은 HIPAA 조직이어도 목록 밖 기능에 PHI 를 흘리면 보호 밖.
  • 목록의 공식 기준은 서명한 BAA. API 는 실수 방지로 막을 것을 자동 차단(400).
  • 막히는 기능의 공통점 = 서버에 무언가를 저장함(Batch 작업 29일, Files, 코드 실행 컨테이너 최대 30일, Managed Agents 세션). 저장을 HIPAA 안전장치 밖에서 하는 기능은 목록에서 빠짐.
  • 클라이언트 쪽에서 도는 도구(Bash·Text Editor·Memory)는 대상. 데이터가 내 환경에 남기 때문.

막는 방식이 약정마다 반대

  • HIPAA 조직 : docs 기능 표에서 HIPAA 열이 No 인 기능 → 400. 단 docs 표 Details 칸에 "안 막힘"이라 적힌 클라이언트 도구(browser use)는 받아주지만 HIPAA 밖.
  • ZDR 조직 : No 기능을 안 막음. 쓰면 그 데이터만 ZDR 밖으로 나가고 그 기능의 보존 정책을 따름.
  • 그래서 "안 막혔다 = 대상" 은 두 약정 모두에서 틀림.

제품마다 목록이 다름

  • API : Skills·Code Execution 막힘.
  • Enterprise 앱 : Skills·파일 생성·코드 실행(네트워크 제외) 대상.
  • Claude Code : HIPAA readiness 대상이 아님. ZDR 을 켰을 때만 BAA 대상(CLI·데스크톱 local). 서버에 세션을 남기는 모드(웹·remote·Remote Control)는 ZDR 과 호환 안 돼 BAA 밖.

Covered Models 와 ZDR 은 서로 밀어냄

  • Covered Models 는 30일 보존이 필수 → ZDR 에서 못 씀.
  • Claude Code 는 ZDR 이어야 BAA 대상 → BAA 아래 Claude Code 로 Covered Models 는 길이 없음.
  • HIPAA-ready API 는 표준 보존이라 Covered Models 가능.

뒤집히는 때

1. 비용을 줄이라는데 Batch 가 답이 아닌 때

  • 조건 : 매일 밤 보험 청구서 3만 장을 요약. 몇 시간 늦어도 됨. PHI 포함. HIPAA 조직.
  • 판단 : 평소라면 Batch(50% 할인)가 첫 답이지만 HIPAA 조직에선 Batch 가 대상 아님 + 접근 불가. 남는 lever = 공통 앞부분 프롬프트 캐싱 · 작은 모델 · Messages API 동기 호출을 나눠 보내기.
  • 등급 : ✓ 확인 (Batch 막힘·캐싱 대상). 동기 호출로 나눠 보내는 방식의 비용은 공식 숫자 없음.
  • 근거 : en-privacy-baa 57·71줄 · ◆ Batch API vs 동기 호출

2. HIPAA 인데 ZDR 이 필요해지는 때

  • 조건 : API 앱은 HIPAA 조직으로 돌리는데, 개발자들이 PHI 가 든 데이터 파이프라인 코드를 Claude Code 로 고치려 함.
  • 판단 : Claude Code 는 HIPAA readiness 대상이 아님 → ZDR 조직이 따로 있어야 BAA 대상. HIPAA 와 ZDR 은 한 조직에 공존 불가 → 조직 둘.
  • 등급 : ✓ 확인
  • 근거 : en-zero-data-retention 52줄 · en-covered-models-baa 49줄

3. ZDR Claude Code 에서 Fable 5.1 을 원할 때

  • 조건 : 위 ZDR Claude Code 조직에서 Fable 5.1 을 쓰고 싶음.
  • 판단 : Covered Models 는 ZDR 에서 못 씀. 워크스페이스 하나를 30일 보존으로 바꾸면 쓸 수 있지만 그 워크스페이스는 BAA 밖 → PHI 금지.
  • 등급 : ✓ 확인
  • 근거 : en-zero-data-retention 115줄 · en-covered-models-baa 40·44줄

4. 한시 예외 : ZDR 로 Fable 5·5.1

  • 조건 : Covered Models 글이 "eligible customers will receive the option to use ZDR with Fable 5 and Fable 5.1 for their own internal business applications" 라고 적음 (Enterprise Frontier Safeguards 로 가는 한시 조치, 2026 가을부터).
  • 판단 : "ZDR 이면 Covered Models 절대 불가" 는 한시 예외가 있음. docs 도 "unless expressly authorized by Anthropic" 라는 단서를 둠. 시험은 2026-07 기준이라 예외 없는 쪽으로 물을 가능성(추론).
  • 등급 : ✓ 확인 (문장) · 시험 뒤 변경
  • 근거 : en-covered-models 34·36줄 · en-zero-data-retention 99줄

미해결

  1. Computer use 가 공식 문서끼리 다름 : docs 기능 표는 HIPAA eligible "Yes"(en-zero-data-retention 145줄, ko 149줄 — "클라이언트 측 도구" 설명), privacy BAA 글은 "Computer Use [beta] — Not covered under Anthropic BAA and not accessible for HIPAA-Ready API users"(en-privacy-baa 61·113줄). 시험 보기면 BAA 글(계약 쪽)이 더 보수적이라 "막힘" 쪽이 안전(추론).
  2. MCP 가 공식 문서끼리 다름 : docs 표는 MCP connector HIPAA "No"(= 기본 400 차단, en-zero-data-retention 153줄), BAA 글은 External MCP "Available to use but sending data to 3rd parties … isn't covered"(en-privacy-baa 63줄). 제3자로 가는 데이터가 BAA 밖이라는 점은 양쪽이 같음.
  3. 일반 API + ZDR 의 BAA 적격 : Covered Models under BAA 글 표는 "Claude API (1P API) · Regular API · Zero data retention → Eligible Service ✅ Yes"(en-covered-models-baa 23줄)인데, 같은 글 11줄은 "HIPAA-ready or (in the case of Claude Code) zero data retention configurations" 이라 적고, docs 는 "PHI 면 HIPAA readiness 가 쓸 방식"(en-zero-data-retention 39줄)이라 적음. API 를 ZDR 로 BAA 를 받는 길이 지금도 있는지 공식 문서끼리 다름.
  4. 공공부문 FAQ(en-public-sector-faqs 30~31줄, 2026-09-28 받은 파일) : "It requires a Zero Data Retention (ZDR) agreement" · "web search is excluded" → 지금 docs·BAA 글과 반대(웹 검색 대상 = en-privacy-baa 24·74줄). 목록 5.4② 가 "옛 문장"이라 한 판단과 같음. 같은 FAQ 의 "BAA 는 Enterprise·직접 API 고객만, Team 플랜 아님"(29줄)은 다른 문서와 충돌 없음.
  5. BAA 판 날짜 : BAA 글은 Enterprise·API 기본 목록에 "*Covered under versions of the BAA accepted after 12/2/25"(48줄), Messages API 세부 기능에 "after 4/1/26"(78줄). 그 전 판 BAA 를 가진 조직의 목록은 원문에 없음.
  6. 목록 5.4② 의 "Claude Platform on AWS·Microsoft Foundry 는 HIPAA readiness 불가" 는 확인(en-zero-data-retention 50줄) — 이 카드엔 없고 ■ HIPAA 구성 에 둠.
  7. 기능 목록의 최종 기준인 HIPAA Implementation Guide(Trust Portal PDF)는 받지 않음(미확인).
