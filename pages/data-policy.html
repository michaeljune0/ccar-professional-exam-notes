개념 설명

원리

학습

  • 상용(API · Claude for Work · Claude Gov) 데이터는 기본 학습 안 함. 보존된 데이터도 명시 허가 없이는 학습에 안 씀.
  • 문이 열리는 곳 = 사용자가 직접 피드백·버그를 보낼 때, 또는 따로 허용할 때. 그래서 "절대 학습 안 함" 은 틀린 문장.
  • 소비자 플랜(Free·Pro·Max)은 다른 글이 적용됨 — 질문지가 상용인지 먼저 봄.

보존

  • 기능마다 저장 필요가 다름. 저장이 필요 없는 기능은 ZDR 이 될 수 있고, 저장이 필요한 기능은 "가장 짧게" 둠.
  • 저장이 꼭 필요한 기능 = 상태를 들고 있는 기능(Batch 작업 · Files · code execution 컨테이너). 이것들은 무보존이 원리상 안 됨.
  • 기본값 문장이 두 공식 문서에서 다르게 쓰여 있음 (미해결 1) → 시험 보기의 단정문을 조심.

ZDR

  • 계약이지 스위치가 아님. 조직 단위로 계정 팀이 켬. 조직을 새로 만들면 다시 켜야 함.
  • ZDR 안에서 "No" 기능을 쓰면 API 가 막지 않음 → 그 데이터만 ZDR 밖으로 나감. 선택의 책임이 고객에게 있음.
  • HIPAA 는 반대 설계 : 조직 전체를 잠그고 대상 밖 기능은 400. ZDR = "안 남김", HIPAA = "남겨도 암호화·접근 통제(access control)·감사 기록으로 지킴".

예외

  • 어떤 약정이어도 법적 요구와 자동 안전 시스템 적발은 예외. 적발되면 입력·출력 최대 2년.

지역

  • inference_geo = 추론이 어디서 도나(요청마다). workspace geo = 저장·엔드포인트 처리가 어디서(워크스페이스를 만들 때 한 번).
  • 둘 다 선택지가 좁음 : 추론 us·global, 저장 us 만. EU 안 처리 요구는 이 lever(손잡이)로 못 맞춤.
  • 미국 전용은 비용이 1.1배. rate limit(속도 제한)은 지역 사이에 나눠 쓰지 않고 공유.

핵심 질문 세 개

  • 이 데이터는 상용 제품에서 나왔나, 소비자 제품에서 나왔나?
  • 이 조직에 무슨 약정(없음 · ZDR · HIPAA)이 있고, 쓰려는 기능이 그 약정 안인가?
  • 지역 요구가 "추론 위치"인가 "저장 위치"인가, 그리고 그 값이 선택지에 있나?

    inference_geo = 요청 단위(POST /v1/messages). 값은 global(기본) · us 뿐 — EU 값 없음. Claude 4.6 이후 모델만(이전 모델에 넣으면 400). us = 입력·출력·캐시 쓰기·캐시 읽기 전부 1.1배(캐시 배수와 겹침). 워크스페이스 기본값·허용 목록(default_inference_geo · allowed_inference_geos)으로 강제 가능. Batch 도 요청마다 지정 (2026-09-28 조회) ✓ 확인 [5.4③] [6.1③]

    workspace geo(저장·엔드포인트 처리 위치)는 따로 : 워크스페이스 만들 때 정하고 못 바꿈, 지금 us 만 (2026-09-28 조회) ✓ 확인

    rate limit(속도 제한)은 모든 geo 공유 ✓ 확인

연습 문제

ZDR 계약을 맺은 조직ZDR 조직이 지연(latency)이 상관없는 대량 요약을 Batch 로 옮겨 반값을 노린다Batch. 자동 안전 시스템에 걸린 요청은 없다안 걸림. 담당자는 "ZDR 이면 Batch 요청은 어차피 거부된다" 고 생각한다. 이 데이터는 어떻게 될까?

시험 대비

함정

  • ≠"Anthropic 은 어떤 데이터도 학습하지 않는다" → 상용 기본값일 뿐, 피드백·명시 허용은 학습 가능, 소비자는 별도 글 ✓ 확인
  • ≠"API 는 기본 무보존(절대)" / "API 는 30일 보존(절대)" → 공식 문서끼리 표현 다름. 조건 없는 단정 보기 주의 ✓ 확인
  • ≠"ZDR 을 요청 헤더로 켠다" → 조직 단위 계약, 조직마다 따로 ✓ 확인
  • ≠"ZDR 이면 어떤 경우에도 안 남음" → 걸리면 최대 2년 · 법적 보존 · "No" 기능을 쓰면 그 데이터는 그 기능 정책 ✓ 확인
  • ≠"ZDR 이면 Batch 가 막힌다" → 안 막음. 쓰는 순간 그 데이터만 ZDR 밖(29일). 400 으로 막히는 건 HIPAA 조직 ✓ 확인
  • ≠"EU 고객이니 inference_geo 를 EU 로" → 값은 global · us 뿐 ✓ 확인
  • ≠"ZDR 조직에서 Fable 5.1 그대로" → Covered Models 는 30일 보존 필요, 그 워크스페이스만 30일을 켬 ✓ 확인
  • ≠"ZDR 조직의 브라우저 앱에서 바로 API 호출" → CORS 불가, 백엔드 프록시 ✓ 확인

뒤집히는 때

1. ZDR 조직이 비용 때문에 Batch 로 옮기는 때

  • 조건 : ZDR 조직, 지연(latency)이 상관없는 대량 작업을 Batch 로 옮겨 반값을 노림.
  • 계산 : Opus 4.6 · 월 입력 4억 · 출력 6천만 토큰 → 동기 = 400 × $5 + 60 × $25 = $3,500. Batch(반값) = $1,750. 절감 $1,750.
  • 대가 : Batch 는 ZDR "No" → 이 작업의 입력·출력은 29일 보존. API 는 막지 않음.
  • 판단 : 지문이 "보존 최소화가 계약 조건"이면 Batch 보기는 오답 쪽. "비용이 우선이고 보존 요구 없음"이면 Batch 가 맞음.
  • 등급 : 계산(가격·보존은 확인)
  • 근거 : pricing ko 9줄(Opus 4.6 $5/$25) · 125줄(Batch $2.50/$12.50) · api-and-data-retention en 166·175·222줄 · 가격 = 2026-09-28 조회값

2. 미국 전용 추론 비용이 판단을 바꾸는 때

  • 조건 : 같은 작업(1번 양)에 "추론은 미국 안에서만".
  • 계산 : global $3,500 → us $3,500 × 1.1 = $3,850 (+$350/월).
  • 전제 : 1.1배가 입력·출력 전부에 붙음(확인). Batch 반값과 us 1.1배를 같이 곱하는 건 명시 문장이 없음 — 캐시 배수가 Batch·데이터 레지던시와 겹친다는 문장만 있음(미해결 5).
  • 판단 : 10% 추가 비용이 비용 제약을 넘기지 않으면 규정 요구가 이김. "비용 때문에 global 로" 는 규정 요구를 버리는 답.
  • 등급 : 계산
  • 근거 : data-residency en 58줄 · pricing ko 89·95줄

3. ZDR 조직인데 Fable 5.1 이 꼭 필요한 때

  • 조건 : 조직 전체 ZDR, 한 팀만 Covered Model 필요.
  • 판단 : 그 팀 워크스페이스만 30일 보존 → 나머지는 ZDR 유지. 조직 전체 ZDR 을 풀 필요 없음.
  • 추가 : Covered Models 글은 "적격 고객에게 한시적으로 Fable 5·5.1 ZDR 선택지"를 말함(Enterprise Frontier Safeguards(EFS) 로 넘어가는 다리). 그래서 "ZDR 이면 Covered Models 절대 불가" 도 단정하면 틀림 — 문서 표현은 "unless expressly authorized by Anthropic".
  • 등급 : ✓ 확인
  • 근거 : api-and-data-retention en 126·142줄 · covered-models en 20·36줄
  • 시험 뒤 변경 Fable 5.1·Mythos 5.1 이 Covered Models 에 추가됨(2026-09-01, 릴리스 노트 en 54줄). Fable 5 는 2026-06-09(릴리스 노트 en 216줄).

4. "EU 안에서만 처리" 요구

  • 조건 : EU 고객 보안팀이 추론·저장 모두 EU 안을 요구.
  • 판단 : 1st-party 는 추론 us·global, 저장 us 만 → 이 요구를 lever 로 못 맞춤. GDPR 자체의 답은 계약(DPA · SCC) 쪽 → ■ 규정별 계약·경로.
  • 등급 : 확인(선택지 목록) · 다른 경로(Bedrock·Vertex 의 EU 리전)는 미해결 4
  • 근거 : data-residency en 102~103줄

5. 보존 기간을 숫자로 단정한 보기

  • 조건 : 보기가 "API 는 0일" 또는 "API 는 30일" 을 조건 없이 말함.
  • 판단 : 두 공식 문서가 다르게 씀 → 둘 중 하나로 단정한 보기보다, 기능·모델 조건(예 : Covered Models 30일, Batch 29일)을 붙인 보기가 안전.
  • 등급 : 확인(두 문장) · 고르는 요령은 추론
  • 근거 : api-and-data-retention en 16줄 · privacy-org-retention en 3줄

미해결

  1. 보존 기본값 표현이 공식 문서끼리 다름 : 플랫폼 docs "not retained by default"(api-and-data-retention en 16줄) vs 개인정보 센터 "automatically delete … within 30 days"(privacy-org-retention en 3줄). 어느 쪽이 시험 키인지 모름.
  2. 2년 예외 범위 : 플랫폼 docs 는 입력·출력 최대 2년만(en 208줄), 개인정보 센터는 분류 점수 최대 7년도 적음(privacy-org-retention en 21줄).
  3. inference_geo 지원 모델 표현 : 릴리스 노트(2026-02-05, en 382줄) "models released after February 1, 2026" vs data-residency "Claude 4.6 and later"(en 33줄). 같은 대상일 가능성(추론).
  4. EU 안 처리 요구의 공식 경로(Bedrock·Vertex EU 리전 등)는 받은 원문에 문장이 없음 — data-residency 는 파트너 플랫폼의 "자체 리전 가격"만 말함(en 62줄).
  5. Batch 반값 × us 1.1배를 같이 곱하는 명시 문장 없음 — pricing ko 89줄은 캐시 배수가 Batch·데이터 레지던시와 겹친다고만 함.
  6. Covered Models 한시 ZDR 선택지(covered-models en 36줄)의 적격 기준·기간 미확인.
  7. 목록 인용 확인 : "Controls where model inference runs, on a per-request basis." · "ZDR is enabled per organization; each new organization requires ZDR to be enabled separately by your account team" 원문에서 찾음. 목록의 "ZDR 은 요청 헤더 아님" 은 원문 문장 아님(조직 단위라서 나온 추론).
