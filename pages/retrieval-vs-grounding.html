ELI5

친구에게 책을 펼쳐 주고 질문했는데 틀리게 답했어요.

  • 먼저 봐요. 내가 펼쳐 준 쪽에 답이 있었나?
  • 없었다면 친구 잘못이 아니라, 쪽을 잘못 펼친 거예요.
  • 있었는데 틀렸다면, "책에 있는 말만 해" 하고 약속을 받아요.
  • 목소리를 낮추라고(설정 바꾸기) 해도 답이 맞아지진 않아요.

개념 설명

원리

두 단계, 두 가지 실패

  • RAG 는 검색(retrieval — 관련 chunk(조각)를 찾아 문맥에 넣음) → 생성(문맥을 읽고 답함) 두 단계.
  • 검색 실패 = 필요한 구절이 문맥에 없음(또는 낡은 판이 들어감). 모델은 없는 걸 못 봄.
  • 생성 실패 = 필요한 구절이 문맥에 있는데 답이 그걸 무시하거나 반대로 말함.
  • 둘을 가르는 건 "실제로 넣은 문맥"을 보는 것 하나. 여기서 갈리면 대책이 정반대가 됨.

검색은 따로 잴 수 있음

  • 공식 실험은 검색만 따로 측정 : 상위 20개 chunk 에 정답 chunk 가 없는 비율(1 − recall@20).
  • 그래서 "검색이 성공했나"는 생성과 분리해 확인 가능한 질문.

생성을 근거에 묶는 수단 (환각 줄이기 문서)

  • 기본 : '모른다' 허용 · 긴 문서(2만 토큰 초과)는 원문 그대로 인용 먼저 · 주장마다 인용, 못 찾으면 철회.
  • 고급 : 단계별 추론(reasoning) 검증 · Best-of-N · 반복 다듬기 · 넣어 준 문서만 쓰기.
  • 이 문서엔 temperature 가 없음. temperature 는 샘플링의 무작위를 조절할 뿐 근거에 묶는 장치가 아님. 게다가 폐기 예정 — Opus 4.6 뒤에 나온 모델은 1.0 외 값을 400 으로 거절하고, 0.0 이어도 완전히 결정적이진 않음.

그 사이에 있는 것

  • chunk 를 너무 많이 넣으면 모델이 산만해질 수 있음 → 구절은 "있는데" 묻힘. lever(손잡이)는 검색 쪽(chunk 수·리랭킹)이지만 증상은 생성 실패처럼 보임.

연습 문제

소파 반품 문의에 넣은 문맥 chunk(조각)에 "가구는 배송 후 7일 안 반품" 구절이 그대로 들어 있다구절 있음. 그런데 답은 흔한 30일 반품 규칙을 섞어일반 지식 "30일 안에 반품돼요" 라고 한다. 팀원은 temperature 를 낮추자고 한다. 무엇을 할까?

시험 대비

함정

  • ≠"temperature 를 낮춘다" → 환각 줄이기 문서에 없음 · Opus 4.6 뒤에 나온 모델은 400 ✓ 확인
  • ≠구절이 문맥에 있는데 "재임베딩·리랭킹" → 검색은 이미 성공, 생성을 근거에 묶음 ✓ 확인
  • ≠낡은 chunk 가 들어갔는데 "grounding 실패(근거 무시)"로 봄 → 낡은 chunk = indexing 문제 ✓ 확인
  • ≠"인용만 뽑게 하면 끝" → 인용을 못 찾으면 그 주장을 철회까지 ✓ 확인
  • ≠"chunk 를 많이 넣을수록 안전" → 더 넣으면 모델이 산만해질 수 있음 ✓ 확인
  • ≠"더 큰 모델로 바꾸면 근거를 지킴" → 근거에 묶는 기법이 먼저 업계 일반
  • ≠Skilljar API 강의(2025 제작 추정)는 "사실 답·일관성엔 낮은 temperature · 0.0 = 완전 결정적" → 지금 docs 는 폐기 예정 · 0.0 이어도 완전히 결정적이진 않음

신호

"For tasks involving long documents (>20k tokens), ask Claude to extract word-for-word quotes first before performing its task."

"If it can't find a quote, it must retract the claim."

"Explicitly instruct Claude to only use information from provided documents and not its general knowledge."

"Inconsistencies across outputs could indicate hallucinations."

"However, more information can be distracting for models so there's a limit to this."

"Deprecated. Models released after Claude Opus 4.6 do not support setting temperature."

"Note that even with temperature of 0.0, the results will not be fully deterministic."

더 깊이 : 뒤집히는 때 · 오답 재료 (설명)

뒤집히는 때

1. 구절은 있는데 25개 chunk 속에 묻힌 때

  • 조건 : 환불 규정 chunk 가 문맥에 있음. 다만 비슷한 chunk 25개와 같이 들어감. 답이 규정과 어긋남.
  • 판단 : 겉으론 "grounding 실패(근거 무시)"지만, chunk 가 많으면 모델이 산만해질 수 있다는 게 공식. 인용 지시와 함께 chunk 수·리랭킹(검색 쪽 lever)도 후보.
  • 등급 : ✓ 확인 (산만해짐) · 25개 예시는 새로 고른 값
  • 근거 : Contextual Retrieval en 125줄(5·10·20 중 20 이 최선, 사례마다 실험)

2. 구절은 있는데 chunk 에 맥락이 없어 못 쓴 때

  • 조건 : chunk 에 "매출이 3% 늘었다"만 있고 어느 회사·어느 분기인지 없음.
  • 판단 : 모델이 근거를 무시한 게 아니라 근거가 불완전. chunk 앞에 문맥을 붙이는 Contextual Retrieval 이 검색뿐 아니라 생성도 도울 수 있다고 공식 글이 적음.
  • 등급 : ✓ 확인
  • 근거 : Contextual Retrieval en 56·127줄

3. temperature 를 여전히 받는 옛 모델

  • 조건 : Haiku 4.5 처럼 Opus 4.6 전에 나온 모델이라 temperature 를 0.2 로 넣어도 400 이 안 남.
  • 판단 : 설정은 되지만 환각 줄이기 문서가 드는 수단이 아님. 0.0 이어도 완전히 결정적이진 않음. 답은 여전히 근거 묶기.
  • 등급 : ✓ 확인 (Haiku 4.5 출시 2025-10-15 → Opus 4.6(2026-02-05) 전)
  • 근거 : messages-create en 598~602줄 · reduce-hallucinations 전문 · 릴리스 노트 en 379·446줄

4. 문맥이 짧아 "인용 먼저"가 조건 밖인 때

  • 조건 : 넣는 chunk 합계가 약 7천 토큰.
  • 판단 : "원문 인용 먼저"는 2만 토큰 초과 긴 문서용으로 적혀 있음. 짧으면 '모른다' 허용 · 넣어 준 문서만 · 주장마다 인용 검증이 먼저 드는 수단.
  • 등급 : ✓ 확인 (조건 문구) · 짧은 문서에 인용 먼저가 해롭다는 공식 문장은 없음 → 보기로 나오면 약한 오답일 뿐
  • 근거 : reduce-hallucinations en 6줄
